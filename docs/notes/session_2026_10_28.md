- `tractatus-iceberg` — Iceberg tables partitioned by `sampled_at_month`

## Iceberg Options Table — Partition Discussion

Current partition spec: `sampled_at_month` only.

**Problem**: No `option_root` partition means any per-root query (dashboard or backtest) scans all monthly partitions.

**Decision**: Add `option_root` to the partition spec alongside `sampled_at_month`.

**Why not done yet**: Requires drop + recreate the Iceberg table + full backfill from `tractatus-lakehouse`. Backfill would take ~1 day. Deferred — log as backlog.

**Backfill script**: `scripts/backfill_local_lakehouse_from_cache.py` already exists and reads from `tractatus-lakehouse` flat parquets. It's ready to use once the table is recreated with the new partition spec. The script is idempotent on `_add_missing_columns` (those columns already exist in the lakehouse parquets). Drop + recreate first to avoid duplicate data.

## Redesign Decision: CacheReader + LakehouseReader

The current `Reader` class conflates two concerns. Decision made to split:

### CacheReader (build next)
- Lives in `tractatus.reader`
- Reads from `tractatus-lakehouse` only (MinIO key listing + `s3://` URIs for DuckDB httpfs)
- Methods:
  - `list_option_roots(provider)` — key listing on `tractatus-lakehouse/options/{provider}/`
  - `list_option_sample_dates(root, provider)` — key listing
  - `get_option_parquet(root, date, provider)` → `str` s3:// URI
  - `ensure_option_parquets(root, after, before, provider)` → `list[str]` s3:// URIs
  - All intraday methods (already on Reader, same MinIO intraday bucket)
- No Iceberg, no fallback, no local downloads
- DuckDB httpfs configured at init

### LakehouseReader (future)
- Reads from `tractatus-iceberg` via PyIceberg
- `options(provider, after, before, roots)`, `level_one`, `order_book`, `fundamentals`, `candles`
- Used for backtests and research, not the dashboard

### Top-level Reader
- Removed for now. Will be reintroduced later as a composition of CacheReader + LakehouseReader with fallback logic.

## Options-Monitor Discovery Redesign

**Problem**: `available_roots()` and `list_option_sample_dates()` hit MinIO on every render cycle. Slow and unnecessary.

**Decision**: Options-monitor maintains its own SQLite discovery table, populated by a nightly background scan.

### SQLite discovery table (in existing options-monitor cache db)
- Columns: `option_root`, `provider`, `first_date`, `last_date`, `updated_at`
- Populated by scanning `tractatus-lakehouse/options/{provider}/` key listing

### Background scanner
- Runs nightly (APScheduler or Streamlit background thread)
- Calls `CacheReader` to list roots and dates
- Upserts into SQLite discovery table
- `available_roots()` and date listing reads come from SQLite — no MinIO hit at render time
